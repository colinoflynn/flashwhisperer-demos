REPLACEMENT_POLICY  =  LRU (measured against FIFO, not assumed)   [high]
==============================================================================
method
  `evict n spacing -k*spacing` walks THROUGH the target, so one access in the
    middle of the interference is a hit. LRU promotes the line and loses it at
    ways+k+1; FIFO ignores the hit and loses it at ways+1. The spacing is the
    measured conflict period of that configuration and k is chosen below its
    measured associativity, so the probe is sized from the geometry rather
    than from a constant
evidence
  eviction-step sharpness over 36 series at spacings that conflict: median 1.000, worst 1.000 (1.000 = every n below N_evict hits and every n at or above it misses)
    waitstates=5 icache=0 dcache=1 prefetch=0 spacing 16: N_evict 8, sharpness 1.000
    waitstates=5 icache=0 dcache=1 prefetch=0 spacing 32: N_evict 8, sharpness 1.000
    waitstates=5 icache=0 dcache=1 prefetch=0 spacing 64: N_evict 8, sharpness 1.000
    waitstates=5 icache=0 dcache=1 prefetch=0 spacing 128: N_evict 8, sharpness 1.000
    waitstates=5 icache=0 dcache=1 prefetch=0 spacing 256: N_evict 8, sharpness 1.000
    waitstates=5 icache=0 dcache=1 prefetch=0 spacing 512: N_evict 8, sharpness 1.000

KNOB_MAP  =  icache -> nothing measured here; dcache -> data_reuse; prefetch -> nothing measured here   [high]
==============================================================================
method
  the full cross-product: for each knob, every pair of measured configurations
    that differ in that knob alone is compared on three metrics (walk
    saturation, the fitted latch model, and the fitted cache geometry (ways,
    conflict period, capacity)). A knob 'controls' a structure when a matched
    pair moves it, 're-indexes' it when the geometry moves at constant
    capacity, and 'masks' it when the probe stops being able to see it
evidence
  icache    -> read_width : no effect    identical in all 4 matched pairs
  icache    -> latch      : no effect    identical in all 4 matched pairs
  icache    -> data_reuse : no effect    identical in all 4 matched pairs
  dcache    -> read_width : no effect    identical in all 4 matched pairs
  dcache    -> latch      : masks        4 of 4 matched pairs moved, 16Bx1 -> all-hit - the probe reads uniformly fast, which hides the latch rather than removing it
  dcache    -> data_reuse : controls     4 of 4 matched pairs moved, 1-way/period 16 B/16 B -> 8-way/period 16 B/128 B
  prefetch  -> read_width : no effect    identical in all 4 matched pairs
  prefetch  -> latch      : no effect    identical in all 4 matched pairs
  prefetch  -> data_reuse : no effect    identical in all 4 matched pairs
  -> read width is moved by no knob, which is what makes it a property of the flash array rather than of the accelerator
  -> no knob reaches the latch; dcache only masks it
  -> multi-line data reuse is controlled by dcache and by nothing else
  -> `icache` moved none of the three metrics. Every primitive here is a data access, so an instruction cache that does not share a structure with the data path is invisible to this probe by construction - this is the expected reading for a separate I-cache, and it is not evidence that the register is inert. The instruction side is not measured: see the cache claim's caveats.
